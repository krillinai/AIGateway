## 1. 目标与范围

管理员能回答四个问题：谁在使用、使用了多少、调用是否正常、请求与响应是什么。

首版覆盖经过 Gateway 的 `POST /v1/responses`、`POST /v1/chat/completions`，包括流式调用。`GET /v1/models`、绕过 Gateway 的模型调用、本地离线操作不计入。

| 本次交付 | 后续按需考虑 |
| --- | --- |
| 用户、智能体、会话、交互轮次维度的调用统计 | 会话/轮次分组浏览、自动会话摘要、业务分类 |
| Token、网关转发成功率、耗时、最近调用时间 | 模型协议内执行成功率、任务完成率、产出质量和效率评价 |
| 限长的用户输入摘录、助手输出及缺失提示 | 完整工具执行、文件变更、Skill 使用还原 |
| 新旧数据入口区分、旧客户端兼容 | 历史日志回填、独立上报停用、旧采集体系删除 |

首版不增加消息队列、定时分析任务、数仓或额外模型调用。只有经过 Gateway 的活动可见，页面始终说明这一范围。

## 3. 请求关联契约

### 3.1 身份与 Header

用户身份始终从 Bearer API Key 解析。客户端不传 `user_id`，服务端不信任正文中的用户名和归属。

| Header | 来源与取值 | 说明 |
| --- | --- | --- |
| `X-Claw-Agent-ID` | 已登记的稳定 Agent ID | 复用现有身份，不为统计创建新 Agent |
| `X-Claw-Session-ID` | 本地逻辑 `threadId`；无会话时用 `runId` | 保持同一会话多轮交互可关联 |
| `x-codex-turn-metadata` | Runtime 自动生成的 JSON Header，读取其中的 `turn_id` 字符串 | ClaweeAgent 的首选轮次来源，无需客户端逐轮改写 Provider 配置 |
| `X-Claw-Turn-ID` | 兼容客户端显式提供的轮次 ID | 仅在原生 Header 不存在时使用；新版 ClaweeAgent 不发送此 Header |

ClaweeAgent 的 `turn_id` 使用 Runtime 执行轮次 ID，不等于模型请求 ID，也不要求等于本地 `runId`。同一 Runtime 轮次中的工具循环和模型请求重试保持该 ID，下一轮由 Runtime 自动更换。首版不把不同 Runtime 轮次按 `runId` 或 `root_turn_id` 合并；原上报继续使用现有口径，两种来源的轮次数不保证完全一致。

原生 Header 的解析示例，其他字段省略：

```http
x-codex-turn-metadata: {"thread_id":"runtime_thread_1","turn_id":"019a9d70-0000-7000-8000-000000000001"}
```

该示例最终仍绑定客户端传入的本地逻辑 `session_id`；原生 `thread_id` 不替代它，避免 Runtime 线程重建时拆散同一本地会话。

处理规则：

1. `agent_id`、`session_id`、`turn_id` 均可选；各来源的 ID 非空值去除首尾空白后须为合法 UTF-8，长度上限 128 个 Unicode 字符，并拒绝控制字符。
2. 携带 Agent ID 时，复用 `AccountService.AccountForAgent` 校验归属用户，再通过 `ProxyGateway.Store().GetAgent` 校验 Agent 存在且状态有效；不新增身份关系。
3. Agent 缺失、格式不合法、归属不符或校验不可用时，不绑定三个标识，记为该用户的“未关联智能体”调用；不改变原模型鉴权和调用结果。
4. Agent 有效时，分别接受合法的会话和轮次 ID；轮次必须有会话才能绑定。原生 metadata 中的 `agent_name`、`installation_id` 等字段不参与身份或归属判断。缺哪个维度就不统计哪个维度，不按时间间隔或对话内容猜测。
5. 存在 `x-codex-turn-metadata` 时，只从该 Header 取轮次：要求单个 Header 值、大小不超过 8 KiB、合法 UTF-8 JSON 对象且 `turn_id` 为合法非空字符串。超限、重复 Header、解析失败或字段缺失/不合法时，轮次不绑定，保留有效的 Agent/会话关联，不回退到可能残留旧值的 `X-Claw-Turn-ID`。仅在原生 Header 完全不存在时，才接受合法的 `X-Claw-Turn-ID`；轮次解析问题不改变模型调用结果。
6. `X-Claw-Agent-ID`、`X-Claw-Session-ID`、`X-Claw-Turn-ID` 只供 Gateway 消费，向模型上游转发时移除；`x-codex-turn-metadata` 沿用现有透传行为。P2 接口只返回提取后的关联 ID，不返回完整 metadata。

其他 OpenAI 兼容客户端不需要改造也能调用，默认进入用户级统计。仅凭 API Key 无法自动区分同一用户的多个智能体。

### 3.2 ClaweeAgent 的最小实现路径

1. 在 `runs/manager.ts` 组装当前执行所属的 Agent ID 和本地逻辑会话 ID，沿现有执行参数传至 app-server host；在 `thread/start` 或首次加载线程的 `thread/resume` 中，为实际模型 Provider 合并这两个稳定的 `http_headers`，保留已有 Provider Header。
2. 同一线程的后续轮次沿用上述稳定标识，轮次由 Runtime 自动附带的 `x-codex-turn-metadata.turn_id` 提供。取消将当前 `runId` 写入 `X-Claw-Turn-ID` 的实现要求，不依赖已加载线程的 `thread/resume.config` 动态刷新 Header。
3. 保持现有 Runtime/host 复用，不为更新轮次标签卸载线程、重启进程或新增本地模型代理。关联 ID 不写进共享配置文件或共享环境变量。
4. `runs/manager.ts` 已在运行诊断中记录 Runtime `turnId`，可与本地 `runId` 核对。本期不新增该映射的上报接口或事实表，也不把映射上报作为 Gateway 轮次统计的前提。

### 3.3 隔离验证结果与联调门槛

已使用 ClaweeAgent 打包的 `codex-cli 0.151.0`、隔离 Runtime 目录和本地模拟 Responses 接口验证：

- 首次请求的自定义轮次 Header 为 `run_a`；同一已加载线程在 `thread/resume.config` 改为 `run_b` 后，模型请求仍携带 `run_a`。原动态 Header 路径不满足逐轮更新要求。
- 同一场景中，原生 `turn_id` 与 `turn/start` 返回的 ID 一致，续聊会自动更新；新旧两个轮次可正确区分。
- 一轮包含工具调用、再次请求模型时，两次模型请求使用同一原生 `turn_id`；模拟上游 503 后重试也保持该 ID。
- 同一 app-server 中两个会话的原生线程/轮次 ID 与各自 `turn/start` 结果对应。该结果不代替真实客户端并发验收。

开发第一步保留对实际打包 Runtime 的兼容验证，并在客户端关联注入及 Gateway 解析接入后验收：

- 首次、多次续聊、同一 host 复用及两个会话真实并发时，Agent/本地会话归属正确，原生轮次随当前执行更新；工具循环和模型重试不增加轮次数。
- Provider 别名、凭据刷新和隔离的审核 Runtime 不串用上下文；没有用户会话的内部调用不因自带 metadata 被绑定为用户交互。
- 原生 Header 与兼容 Header 的优先级、非法 metadata 的降级、缺失关联及旧客户端调用符合第 3.1 节；Runtime 版本升级时重复这些兼容用例。

上述隔离验证仅覆盖 Runtime 0.151.0 的 Responses 请求，不代表客户端完整链路、其他 Runtime 版本或其他协议已通过。联调不通过的维度保留为空，先交付已验证的用户级或 Agent/会话级统计，不宣称完成轮次迁移，也不自动引入代理或 Runtime fork。

## 4. 数据结构与写入

### 4.1 扩展现有审计表

通过新的 Goose 迁移为 `model_proxy_audit_records` 增加以下字段，不新建第二套活动事实表：

| 字段 | 类型及默认值 | 用途 |
| --- | --- | --- |
| `agent_id` | `TEXT NOT NULL DEFAULT ''` | 已验证归属的智能体 |
| `session_id` | `TEXT NOT NULL DEFAULT ''` | 会话关联 |
| `turn_id` | `TEXT NOT NULL DEFAULT ''` | Runtime 执行轮次 ID，或按第 3.1 节接受的兼容轮次 ID |
| `activity_content` | `JSONB NULL` | P2 内容摘录及采集标记；历史记录保持 NULL |

`activity_content` 固定结构示例：

```json
{
  "schema_version": 1,
  "input_text": "整理本周的工作记录",
  "output_text": "已整理以下内容……",
  "input_status": "available",
  "output_status": "available",
  "input_truncated": false,
  "output_truncated": false
}
```

输入状态为 `available | unavailable`；输出状态为 `pending | available | partial | unavailable`。文本缺失不写占位正文，由页面根据状态显示提示。截断与状态分别记录，部分输出也可能被截断。

新增部分索引 `(created_at DESC, audit_id DESC) WHERE activity_content IS NOT NULL`，优先覆盖不筛选用户的默认查询；用户查询继续复用现有 `(user_id, created_at DESC, audit_id DESC)` 索引。使用代表性数据检查执行计划后，再按实际需要补充 Agent 或会话索引。

### 4.2 写入顺序

1. 模型接口成功解析合法 JSON 后，随现有审计创建写入关联字段、输入摘录和 `output_status=pending`。非法请求不设置 `activity_content`；`/models` 不设置。
2. 后续鉴权策略拒绝仍沿用原审计状态；统计查询排除 `rejected_api_key`、`rejected_scope`、`rejected_account`，不把拒绝访问算作使用活动。
3. 转发响应时只在内存中累计限长输出。结束、失败、超时或客户端断开时，与原有终态及用量一起更新同一条记录。
4. 原有审计创建失败继续拒绝调用。内容解析不支持或超限只改变内容状态，不改变响应字节、不触发模型重试。

一条进入网关的模型请求只产生一条审计记录。现有上游故障转移及用量累计逻辑继续使用，不按 SSE 分片、上游尝试或更新次数重复计数。

## 5. 输入与输出提取

### 5.1 用户输入摘录

- Chat Completions：取 `messages` 中最后一条 `role=user` 的可读文本。
- Responses：`input` 为字符串时取该字符串；为数组时取最后一条 `role=user` 的可读文本块。
- 不提取 system/developer 指令、推理正文、工具参数/结果或媒体二进制。只有图片等媒体而无文本时标记不可用。
- 使用 `previous_response_id` 且本次没有用户文本时标记缺失，不跨请求猜测补全。

此字段是“请求中的用户输入摘录”，不保证每条请求都包含新用户消息。同一轮重复携带历史上下文时，各请求仍分别展示自己的摘录；首版不提取轮次级输入，不做全量对话差异计算。

### 5.2 助手输出

| 协议 | 非流式 | 流式 |
| --- | --- | --- |
| Chat Completions | `choices[0].message.content` | 拼接 `choices[0].delta.content` |
| Responses | `output` 中助手消息的 `output_text` | 按消息/文本块拼接 `response.output_text.delta` |

Responses 的 `response.output_text.done`、`response.completed` 可能再次携带完整文本，只用于补全/校准对应文本块，不再次追加。只记录文本；没有可读文本的工具调用响应显示“本次无文本输出”，不解释为任务完成。

SSE 按完整事件解析，处理任意网络分片边界和结束事件。客户端断开、流错误或缺少正常结束标记时，已有文本标为 `partial`；空输出标为 `unavailable`。这不改变既有审计成功/失败状态的语义。

### 5.3 限长与脱敏

输入、输出各最多保存 8000 个 Unicode 字符，截断后保持合法 UTF-8；SSE 内容解析单个事件缓存最多 64 KiB，超限时保留已取得文本并标记截断。停止累计文本后仍继续原有响应转发和用量解析。

新摘录复用 `server/internal/office/claweeactivity/types.go` 的现有文本脱敏规则，匹配范围与现有活动上报一致，本期不扩展规则。流式文本在限长缓冲内拼接后，统一应用现有规则再落库；完整落入缓冲且符合现有模式的内容按规则处理，包括跨网络分片的内容。首版验收仅覆盖现有规则能够识别的完整内容，不承诺识别任意凭据，也不保证覆盖正文中的引号键值或截断后不满足匹配模式的凭据片段。不得在 access log、错误日志中打印正文。

不保存图片、音频等原始内容；原审计快照继续执行现有媒体脱敏策略。页面按纯文本安全渲染摘录。

## 6. 统计口径

统一 P2 数据条件：`activity_content IS NOT NULL`，限两个模型 POST 入口，并排除第 4.2 节的鉴权拒绝状态。所有接口使用该条件；汇总与列表再按 `created_at` 应用查询区间及筛选条件。请求详情仅按 `audit_id` 和 P2 数据条件查询，不受页面时间范围或筛选条件限制。

| 指标 | 规则 |
| --- | --- |
| 请求数 | 范围内审计记录数；配置失败、上游失败、断开均保留 |
| 活跃用户 | 请求中 `user_id` 去重 |
| 活跃智能体 | 非空 `(user_id, agent_id)` 去重；未关联调用不增加智能体数量 |
| 会话数 / 交互轮次 | 非空 `(user_id, agent_id, session_id)` / 再加 `turn_id` 去重；不称为完成任务数 |
| 网关转发成功率 | `succeeded / 已结束请求数`；`started` 不进入分母，无已结束请求时返回 NULL；沿用现有 HTTP/传输状态语义 |
| Token | 累加审计记录中的已知用量，沿用 `usage_status`；部分/缺失用量单独提示，全部缺失显示 `--` |
| 平均耗时 | 已结束请求 `duration_ms` 的平均值；无数据时 NULL |
| 最近调用时间 | 范围内 `MAX(created_at)`，不称为心跳 |
| 请求处理中 | `started` 且距创建未超过现有 15 分钟请求上限加 2 分钟余量；更久显示“状态待核对” |

交互轮次按第 3 节确定的 `turn_id` 去重。ClaweeAgent 的该指标表示已关联的 Runtime 执行轮次数，不等同于本地 `runId` 数、用户消息数或旧上报轮次数；同一本地运行若产生多个 Runtime 轮次，分别计数。

Token 按每次真实调用累计。历史上下文重复发送也会消耗 Token，不因消息去重扣减；缓存、推理 Token 继续沿用现有用量契约，不重复加进总 Token。

网关转发成功率不判断模型协议内的执行结果。例如 HTTP 200 的 SSE 包含错误事件后正常结束，现有审计仍可能记为 `succeeded`，内容状态则可能为 `partial`。页面同时展示部分输出提示；首版不修改审计状态机。

时间范围复用现有活动统计的 `today | 7d | 30d` 和服务端时区，使用 `[start, end)`；不另建日期规则。最近调用不证明客户端在线；请求结束也不证明本地工具或业务任务已经结束。

## 7. 管理接口

新增三个只读接口，使用 `/api/v1/admin` 账号登录及现有 `console:activity:read` 权限。不要复用要求 `console:mcp:audit:read` 的模型审计详情接口，避免活动页面出现权限错配。

| 接口 | 参数与返回 |
| --- | --- |
| `GET /activity/model-overview` | `range` 默认 `7d`，可选 `user_id`、`agent_id`、`unattributed`；返回 `summary`、分页 `agents`、`meta` |
| `GET /activity/model-requests` | 相同范围/用户/智能体过滤，可选 `session_id`、`turn_id`；返回分页请求元数据及每段最多 160 字符预览 |
| `GET /activity/model-requests/detail?audit_id=...` | 仅按 `audit_id` 和 P2 数据条件返回请求元数据、`activity_content`；不接收时间范围或主体筛选，不返回原始 Header、请求体、响应体或 API Key 字段；摘录按第 5.3 节处理 |

统一响应包装为 `{ "data": ... }`，错误沿用项目的结构化格式：未登录 401、缺少权限 403、参数错误 400、记录不存在或不属于 P2 范围 404、模型活动能力不可用 503。空结果是 200，不把数据库失败伪装为空列表。

契约补充：

- `model-overview` 的 `summary` 包含第 6 节指标、完整/部分/缺失用量请求数。`agents` 按 `(user_id, agent_id)` 聚合，每行包含主体标识、显示名称及示例中的统计字段；空 Agent 聚合为对应用户的“未关联智能体”行。
- `agents` 使用 `page`、`page_size`，默认 1、20，最大 100；按最近调用时间倒序，再按用户/Agent ID 排序。`meta` 返回总行数，摘要不受分页影响。
- `model-requests` 复用现有 `(created_at, audit_id)` 倒序游标，`limit` 默认 20、最大 100。下一页同时传 `cursor_created_at`、`cursor_id`，取自 `meta.next_created_at`、`meta.next_id`；只传其中一个返回 400。时间使用 RFC3339Nano；无下一页时返回 `null`、空字符串。查询范围与筛选变化后清空游标。
- 过滤未关联行使用 `unattributed=true`；它与非空 `agent_id` 互斥。筛选会话/轮次必须同时指定用户、Agent，轮次还须指定会话，防止跨主体同名 ID 混合。
- 请求元数据包括 `audit_id`、三项关联 ID、用户、模型、时间、状态、错误码、Token/用量状态及耗时；预览从按第 5.3 节处理后的摘录生成。用户显示名称优先，其次邮箱/手机号/ID；Agent 名称缺失时显示 ID，空 Agent 显示“未关联智能体”。
- `meta` 固定返回 `source=model_proxy`、`schema_version=1`；汇总与列表另返回 `range`、`timezone`、`start`、`end`。不查询首条采集时间，空结果统一提示“当前范围无模型调用”。
- 响应字段以以下示例为准。计数为非负整数；`success_rate` 为 0～1 的数值或 `null`，显示名称为“网关转发成功率”；`avg_duration_ms` 为数值或 `null`。全部缺失用量时 `total_tokens=null`，已知用量为零时返回 0。请求未结束时 `completed_at`、`duration_ms` 为 `null`；汇总无调用时 `last_request_at=null`。缺少关联的 ID 和不可用的文本为 `""`，空列表为 `[]`；字段不因空值省略。

## 8. 页面调整与兼容切换

### 8.1 `/admin/activity` 新默认视图

- 顶部：请求数、活跃用户、活跃智能体、总 Token、网关转发成功率；补充用量缺失提示。
- 筛选：今天/近 7 天/近 30 天、用户、智能体。
- 主列表：用户、智能体、请求数、会话数、交互轮次、Token、最近调用时间；轮次说明提示按第 3 节的执行轮次统计，与原上报口径可能不同；不再展示在线和心跳。
- 详情：选中智能体后展示按时间倒序分页的请求列表，显示会话/轮次 ID，并支持按这些 ID 精确筛选；展开单条请求查看输入摘录、助手输出及错误码对应的失败提示。缺少关联信息时 ID 显示 `--`。首版不分组浏览、不跨页拼接轮次，也不全量拉取请求。
- 首版加载页面、切换筛选或翻页时查询，并提供手动刷新；不增加定时轮询或服务端推送。

新视图使用独立数据 hook/类型，不把模型请求强行转换为旧 `OfficeSnapshot`。复用现有组件和样式；请求无文本、内容截断、部分输出、用量缺失有明确提示。

### 8.2 发布顺序

1. **Gateway 先上线**：增加字段、采集、新查询和管理台视图。老记录的 `activity_content` 保持 NULL，不自动回填正文或猜测关联。
2. **客户端随后上线**：携带稳定的 Agent/本地会话 Header，轮次使用 Runtime 原生 metadata，保留原活动上报行为与开关。新统计只读模型审计，不与上报表合并，因此两路采集同时存在时不重复计数。Gateway 同时兼容仅提供 `X-Claw-Turn-ID` 的调用；没有有效 Agent Header 的旧客户端仍进入用户未关联行。
3. **两仓联调**：确认模型活动统计、请求关联与旧入口兼容。本期不关闭独立上报；后续如需停用，再单独评估依赖入口与兼容影响。

原上报视图保留为“客户端上报记录”，通过 `/admin/activity?source=reported` 访问，继续按原上报配置更新并标明来源。原列表/详情接口和旧 `collector_id` 详情链接继续有效；新视图详情显式使用 `source=model_proxy` 及用户/Agent 标识。

P2 不迁移 `/app/activity`、活动 MCP 数据视图及 Skill 统计的口径。这些入口继续依赖原上报体系，本期不增加采集截止说明或停用改造。不得把完成 P2 描述为这些入口也已完成迁移。

回退时恢复旧管理视图，保留新增字段和日志，不执行删除审计数据的 Down 迁移；原上报行为与开关保持不变。

## 9. 开发顺序与验收

| 顺序 | 工作 | 完成标准 |
| --- | --- | --- |
| 1 | 原生轮次解析与实际 Runtime 兼容验证 | 稳定 Agent/会话 Header、原生轮次与兼容回退符合第 3 节；首次、续聊、复用、并发及重试标识正确，失败按第 3.3 节收敛范围 |
| 2 | Gateway 迁移、采集与脱敏 | 同一审计记录保存关联和限长文本；流式转发与现有用量统计正常 |
| 3 | SQL 与管理接口 | 汇总、列表、详情口径一致；权限与主体隔离正确 |
| 4 | 管理台新视图和来源入口 | 请求分页、精确筛选与手动刷新可用，状态命名准确，旧链接有效 |
| 5 | 两仓联调与旧入口兼容 | 稳定关联 Header 与原生轮次正确，新视图仅从模型审计取数，原上报与旧入口保持兼容 |

使用合成数据和隔离数据库验收，至少覆盖：

1. 同一 Runtime 轮次 3 次模型调用：请求数 3、交互轮次 1；下一轮使用新的原生 `turn_id`，轮次增加且本地会话保持不变。工具循环、上游重试及两个会话并发时不串用轮次；同一本地运行的不同 Runtime 轮次不按 `runId` 合并。
2. 两用户使用相同 session/turn 字符串仍分别统计；越权 Agent 标识不产生错误归属；无 Header 的调用进入用户未关联行。
3. `/models`、非法 JSON、鉴权策略拒绝均不增加活动；配置失败、上游失败、断开仍保留调用记录；未结束请求不进入网关转发成功率分母。协议内错误与部分输出不改变原审计状态语义，页面提示准确。
4. Chat/Responses、流式/非流式的文本可读；任意分片、重复终态全文、超限事件、工具循环均不重复输出或计数。
5. 超时/断开后内容标记部分或缺失；陈旧 `started` 不永久显示处理中；Token 缺失显示 `--`，部分用量有提示，故障转移沿用已确认的用量。
6. 复用现有文本脱敏用例，验证完整落入缓冲且符合现有规则的内容在数据库新摘录和页面中按规则脱敏，包括跨网络分片的内容；不把任意凭据识别或截断边界覆盖列为本期验收保证。媒体二进制不落入摘录。
7. 无活动权限无法访问列表/详情；有活动权限可查看摘录，不能借此取得原始模型审计 Header/正文。
8. 旧上报与模型采集同时存在不重复计数，旧记录不混入新口径；原上报行为与开关不变，旧入口与链接继续有效。
9. 同一轮超过一页时，请求按游标连续分页，无遗漏或重复；会话/轮次筛选按完整主体生效，不要求跨页分组或轮次级输入。详情仅按 `audit_id` 与 P2 数据条件读取，切换页面时间范围不影响该请求的详情链接。
10. 三个接口的字段、空值、分页和错误响应符合第 7 节；空结果显示“当前范围无模型调用”，手动刷新可用，默认总览与请求列表使用代表性数据核对执行计划。
11. 原生 Header 与 `X-Claw-Turn-ID` 同时存在时使用原生值；原生 Header 存在但重复、超限、JSON 非法或 `turn_id` 缺失/不合法时，不绑定轮次且不回退到旧值，有效 Agent/会话关联及模型调用结果不变。原生 Header 不存在时接受合法兼容 Header；只有原生 metadata 而没有有效 Agent Header 时，不自动建立智能体、会话或轮次归属。

服务端执行针对解析器、统计、权限的测试及隔离 PostgreSQL 集成验证；管理台执行相关测试、类型检查和构建。提交/发布前继续遵守两仓 AGENTS.md 的完整检查要求；客户端可执行代码修改后必须通过 `desktop:preflight:local`。本文交付仅为方案，不代表上述验证已通过。
